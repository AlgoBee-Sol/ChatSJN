# Question-handling investigation — 29 October 2026

## Confirmed root cause and reproduction

The saved failing request was found in live D1 with `mode=clarification`, `category=OTHER`, and the exact predefined Urdu category-selection message. Its timestamp is `2026-10-23T22:00:10.146Z`. The saved question uses **رائج / غیر رائج**; the supplied regression uses **راجح / غیر راجح**. Both were investigated, without treating those words as synonyms.

At commit `a59ce68`, `apps/worker/src/ai.ts:answer()` returned `messages.clarify` immediately when `category === 'OTHER'`. The shared keyword classifier did not recognize this question. That deterministic branch bypassed retrieval, embeddings, generation and citation validation. The historical response was not generated by the language model.

The later educational-only release (`60c544e`) restricted the shortcut to `FIQH_ENABLED && category === 'OTHER'`. With the flag currently false, the October 28 deployment already searched this question. Fresh baseline requests confirmed that fact. Replaying an old request ID or viewing saved conversation history still shows the old persisted answer; the fix does not rewrite historical messages.

The dormant topic-based rejection has now been removed from **both** backends, including a regression with Fiqh enabled. Clarity is evaluated separately from subject classification. Unrecognized but explicit questions search eligible educational sources; narrowly recognized subjectless requests ask for the missing subject.

## Retrieval findings and measured changes

The original Urdu expression used its eight slots on `ایران، اندر، عظیم، انقلاب، رونما، ہونے، سلسلے، راجح`, dropping **نظریات**. The opening article passage was still lexical rank 1 and semantic rank 1 (cosine approximately **0.597**, above the unchanged **0.45** threshold). It was not lost at semantic ranking. The original 12 candidates did not include this article's continuation/critique passages 1 and 2.

Baseline English and Roman Urdu live answers did **not cite the relevant article**. Their variable generated keywords found broader revolutionary material. Content review found questionable substitutions of other theories; the Roman Urdu explanation also used Arabic script. A fresh vague request, `اس کے بارے میں بتائیں`, incorrectly produced an unrelated grounded answer.

Controlled aliases now preserve Iran/revolution/theory concepts across Urdu, English and Roman Urdu. Urdu نظریات expands to نظریہ; **راجح is never aliased to رائج**. With the new Urdu query, article chunk 0 remains lexical rank 1 and continuation chunk 1 moves to rank 2. With the English/Roman alias query, chunks 0, 1 and 2 enter the 12-candidate set. An independent BGE-M3 check against the reported Urdu question ranked these three at approximately **0.597, 0.542 and 0.559** respectively; several unrelated candidates fell below 0.45. Scores vary slightly between inference batches and are not confidence or scholarly preference.

Candidate count remains **12 per attempt**, selected evidence remains **at most five**, and the threshold remains **0.45**. If a recognized educational topic yields no eligible documents, no keyword hits, or no semantically qualifying evidence, retrieval retries once across eligible educational topics. This can evaluate up to 24 candidates across two attempts; source approval, authority and category remain mandatory. Fiqh retrieval never broadens to educational sources or another authority. Optional keyword translation failures no longer prevent original-language FTS.

## Answer safety

Generation instructions explicitly distinguish source criticism from consensus, describe conflicting accounts with their citations, and prohibit using retrieval rank as a scholarly judgment. The Worker supplies an explicit per-request language instruction.

Live content review demonstrated that a general instruction alone did not reliably distinguish **راجح** from **رائج**. A narrow evidence-aware safeguard now supplies that specific terminology difference when the question asks about rajih but the retrieved text only uses raij. If the model fails to acknowledge it, or cannot establish the requested preference, the response abstains with an explanatory terminology note. This check does not silently correct the question or invent the scholar's preferred theory.

Existing citation ID, duplicate-reference, exact-quote, authority, approval and final persistence checks remain in place. Unsupported answers still produce an insufficient-evidence response, not a request to choose Quran/Aqaid/history/Akhlaq.

## Remaining limitations

- Lexical-first retrieval can still miss new synonyms or paraphrases beyond the controlled vocabulary. No whole-corpus vector index was introduced.
- Topic fallback only runs when the initial topic search returns no qualifying evidence; plausible but incomplete evidence may still need broader evaluation.
- The ambiguity rule deliberately recognizes a small set of subjectless prompts. Resolving pronoun-only follow-ups from conversation history remains limited and may require restating the subject.
- The terminology check is a narrow guard for the demonstrated word confusion, not general semantic entailment verification. Valid citations and a passing model sample do not guarantee every generated claim, interpretation, or attribution.
- Conflicting-source tests verify evidence delivery, policy and citation validation using synthetic fixtures; they are not scholarly validation of a real dispute.
- No new UI behavior was introduced. Existing browser journeys were not rerun in this investigation; authenticated API/runtime checks covered the changed backend.
